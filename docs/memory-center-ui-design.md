## 3. 两种可比较方向

| 评审维度 | A：清爽阅读 | B：紧凑管理 |
|---|---|---|
| 主要用途 | 找一条相关经验、读内容和来源 | 比较多条状态、筛出同类记录、选择一组继续查看 |
| 列表呈现 | 标题 + 短摘要 + 来源/时间；无独立卡片包裹每条 | 选择 / 记录与来源 / 状态 / 更新时间，少量横线 |
| 详情 | 与列表接近等宽，正文、依据和适用范围逐级展开 | 列表略宽，详情略紧凑，信息顺序相同 |
| 筛选/选择 | 搜索和状态即可，减少常驻工具 | 同样的搜索和状态；选择栏只用于预览选中项，不捆绑批量写入 |
| 代价 | 同屏记录数较少，需要滚动 | 长标题可能多行；高密度使来源阅读稍慢 |
| 窄屏 | 单列列表 → 详情 → 返回列表 | 保留记录和状态，更新时间移入详情；没有整页横向滚动 |

建议先评审 A：记忆的主要价值是能判断内容是否有依据，正文和来源应有更高阅读优先级。B 适合频繁整理较多记录时再选择。**建议不等于用户选择；当前默认显示 A 仅用于开场展示。**

评审问题只保留一个高层选择：

> 背景与目的：记忆中心已经确定采用列表和侧边详情，现在需要决定日常管理更偏“读清内容来源”还是“快速比较筛选多条”。建议选择 A 清爽阅读，阅读负担较低；B 紧凑管理能容纳更多记录，但需要更密集地比较列。请整体选择 A、B，或指出最影响判断的一处布局问题。

用户答复：**待完成**。用户使用前的判断预测（哪一方向能更快找到并理解一条记忆）：**待完成**。原型技术检查与用户选择分别记录，不能代用户填写。

## 4. 页面结构与组件

### 4.1 页头与分区

页头只有“记忆中心”、一句用途说明和项目上下文，不放总量、召回率、置信度或趋势卡。分区为“经验记忆 / 年度工作记录 / 处理任务 / 项目摘要与共享”，当前分区用文字和下划线共同标识。

项目 picker 属于应用上下文，不能把 UI 传入的任意 scope 当成授权。离线原型切换项目仅更改预览上下文提示，数据仍明确是一组合成记录；并未模拟第二个数据源、读取真实项目或证明项目隔离。未来实现需依现有可信项目 ID/绑定权限加载。

搜索栏标注“搜索当前分区”，避免让用户误认为可跨所有本地目录检索。首版保留状态筛选；B 的选择不自动执行批量纠正、删除或合并。搜索/筛选变化会清空勾选，渲染时再取当前结果的选择交集；“查看首条所选”只允许打开当前可见对象。真正批量写入不是此次视觉方向的默认范围。

### 4.2 经验记忆

列表最小字段：标题、未核验/归档状态、来源方式、来源短名、更新时间。A 显示一段短摘要；B 把状态对齐到列。详情顺序：类型 → 标题/状态 → 完整内容 → 来源与依据 → 记录信息 → 局部动作。**v0.3.0 普通经验的 verification 固定为 unverified，没有普通经验的“已核验”状态或核验按钮。** 原型全部经验遵守这一现状；“本人保存 / 模型提炼”是来源方式，不能代替核验。已归档的内容也仍未核验。核验状态不是模型置信度，也不允许把“有来源”显示为“已证明”。

归档就地说明“内容保留、可恢复、不参与自动召回”。原型目前仅展示阅读子集，不能据此删除现有管理能力。未来选定方向后，已有**纠正、归档、恢复、明确删除**保留在详情局部动作中，按记录状态启用相应动作；明确删除不可恢复，与归档/冷档分开，也不承诺撤回模型已经收到的内容。此次不添加可执行删除或恢复演示。

“整理记忆（设计预览）”在本原型只是跳转到合成候选。未来如果实施，入口应先给出范围、输入前提与估计代价，生成独立候选批次；不能在点击入口时静默覆写原记忆。候选实际规则以独立整理设计为准，本稿不定义存储 schema 或 API。

### 4.3 年度工作记录

与经验明确分区，正文围绕背景、本人贡献、结果组织。缺证状态贴近具体记录；引用名、引用定位和正文已读/未读需要分开表达。当前原型显示“结果待补证明 / 待确认 / 贡献已确认”合成记录状态。本人贡献确认仅覆盖相应事实，不代表结果、所有断言或证明均已证实。

**报告审定是另一个对象**：未来呈现报告时，需要绑定报告版本和来源版本（当前实现为 `reportDigest + sourceRevisions`），不能把报告曾经获审定的状态贴到一条工作记录上。当前原型不提供报告级审定对象或操作，仅在详情说明其区别；没有“普通记录已审定”的绿色状态。

“查看证明引用演示”只在页脚显示示例引用名，不打开真实文件。证明正文审批链尚未打通，不提供看似可用的正文阅读按钮。年度维度模板仍待用户提供，不猜测评分维度。

### 4.4 处理任务与整理候选

统一处理任务中分别显示普通任务和标为“设计候选”的整理批次。任务标题说明对象和动作，状态贴近标题；异常需解释用户当前能判断什么。

整理详情固定显示：①原记录逐条完整内容；②候选表述；③变化说明；④分别保留的来源；⑤待评审/已决定状态。候选 DEMO-C01 的 `sourceIds` 引用经验中实际存在的两个合成对象 DEMO-E03、DEMO-E05，原文和独立来源/定位/版本直接由这些对象生成，不另写缩略“原文”。数量为 2 条原记录、2 个来源，完整展示记录构建标识、核对运行产物和无法核对时不得下已验证结论的条件。原型的“演示：采用候选”“演示：保留原文”只改当前页面状态，不执行数据迁移、不设置任务完成、不消费 Provider。

v0.3.0 的取消入口仍返回 `CANCEL_UNAVAILABLE`：本原型用 disabled 按钮配可见原因，不能展示可成功取消的动效。结果未知不能直接重发；技术原因码可放详情，不应以英文异常堆栈代替用户说明。

### 4.5 项目摘要与共享

列表显示项目摘要与适用性，详情保留版本、来源和范围。共享用“来源 Boreal → 目标 Atlas”的短关系描述；不画扩展知识图谱。已退休项目内容保留，“适用性待核”在标题附近；不能把历史摘要包装为当前事实。

新建/撤销共享、摘要刷新等已有能力没有因视觉原型得到新的端到端验收；本原型不连真实 API。冷档/恢复/语义再压缩未实现，不出现可用按钮或成功结果。

## 5. 状态与反馈合同

| 场景 | 页面行为 | 行为与证据边界 |
|---|---|---|
| 初次进入 | 稳定页头、工具栏和首条详情；窄屏先列表 | 本原型由合成数据同步渲染，不能证明实际载入性能 |
| 查询中 | 保留原结果，按钮/局部区域反馈正在查询 | 将来依实际请求状态渲染；原型未伪造网络 loading |
| 无记录 | “这里还没有记录”，给适用的已有入口 | 不能以此暗示自动提炼已开启 |
| 搜索无结果 | “没有匹配的记录”，建议缩短词或还原筛选 | 原型可实际触发；选中记录不在结果时详情不继续显示旧内容 |
| 选中记录失效/删除 | 清空该详情，说明记录已变化，返回列表 | 将来由现有响应/版本重核触发；不默默切到另一条并沿用旧状态 |
| 来源不足 | 标明缺失的来源/证明，不用绿色成功状态 | “引用存在”与“已读取/已核验”分开 |
| 项目不可用/已退休 | 显示当前可用性/适用性，保留历史阅读 | 不扩大 scope 回退其他项目，不擅读本地目录 |
| API 错误/离线 | 就地说明原因与可执行恢复，保留输入 | 后续依响应码；不因失败显示成功提示 |
| 结果未知 | 先核对结果，抑制盲目重发 | 原型只有状态呈现，没有真实核对/重试功能 |
| 提交冲突/版本变化 | 拒绝把旧候选当现用内容，重新审阅受影响项 | 这是未来设计约束，原型不宣称已执行版本验证 |
| 整理候选拒绝 | 保留原文，并使该候选决定可追溯 | 原型只演示页内反馈，不写入实际记录/账本 |

反馈只在计数或动作结果改变时用 `aria-live="polite"`，不每次悬停播报。装饰色不承担单独状态含义；每个状态有完整文字。

## 6. 自适应、键盘与可访问性

桌面双栏依可用宽度分配；A 大致 1:0.94，B 大致 1.2:1。760px 以下切为列表与详情的单列阅读模式：打开记录后显示“返回列表”，同时折叠搜索/状态筛选/整理工具栏及状态说明行，减少正文前的冗余；返回后恢复原搜索和筛选。页头项目、当前分区、详情类型、返回及标题保留。没有叠层焦点陷阱、整页横向滚动、固定页脚或多级抽屉。

普通记录点击、“整理记忆”跳转和 B“查看首条所选”统一走 `openDetail`，先核对对象属于当前结果，再切换详情；窄屏焦点进入可见返回按钮。返回或 Escape 恢复当前可见记录按钮；若记录已不在结果中，回到可见搜索字段。空详情保留返回按钮，且失去当前结果的详情自动回到列表模式，不会把列表隐藏后留下空白死路。一般重渲染也不把焦点恢复到隐藏或 disabled 控件。

320px 下四个分区排两行；工具栏自然换行；长标题、状态、来源和 ID 可以断行。表格保留标题/来源与状态，更新时间已在详情完整提供。系统缩放/200%文字时不能靠固定高度裁切内容。原型阶段没有虚拟列表和无限滚动。

使用原生 button/input/select/table；字段有可见 label。分区采用导航按钮与 `aria-current`，不假装已实现完整 roving-tabindex 的 ARIA tabs。正常 Tab 顺序与视觉顺序相同；Enter/Space 使用原生语义。列表标题是可访问按钮，点击行也只由该按钮的扩展点击范围实现，选择框和按钮不互相嵌套。B 当前阅读项按钮单独用 `aria-current` 标记，复选框只表达勾选，二者不合并。重新渲染后保留可见记录/动作/选择框焦点；没有依赖 hover 的唯一动作。会话宿主恢复状态时，query/filter 按分区允许值恢复；无效 filter 回到全部，不恢复隐藏选择。

细指针控件保持桌面密度；粗指针主要目标至少 44px 高。窄屏 input/select 显式设为 16px，不能依赖 `.mc-field` 的 12px 说明文字继承。普通正文对比目标至少 4.5:1，必要控件边界至少 3:1；宿主实际 light/dark 令牌仍需分别测量。原型不移除系统缩放，不添加非必要动画，减少动效偏好下没有额外变化。

## 8. 原型与未来 React 的边界

交付文件：

- [离线交互原型](ui-review/memory-center-review.html)：完整 HTML，自包含 CSS/脚本，原生系统字体，无 CDN、外部图片、脚本、字体、依赖或网络请求；CSP `connect-src 'none'`。
- 会话内评审 fragment：`C:/Users/admin/.codex/visualizations/2026/11/02/01a19cde-008c-7420-b014-ec129c986e5a/memory-center-review.html`，一个宿主 variant carousel，两个完整方向；不自写宿主轮播导航。产品样式用局部令牌，跟随宿主 light/dark。离线包装由同一 fragment 生成，只在包装外围添加 A/B 导航，因此交互和文案不分叉。

renderer-free 指原型**没有加载 React/宿主 renderer 或 Harness**，不意味着原型已能直接装入宿主。它用页内合成数据和局部状态表现导航、搜索、状态筛选、选中/返回、候选对照。它不接真实 API、不连接 SQLite/Provider、不调用宿主授权、不读本地证明、不执行任何产品写入。会话内可选的宿主 widgetState 仅记评审界面状态，不能代表写入记忆；离线没有该宿主接口，刷新即重置。

未来实施时不整段复制原型 DOM 脚本或用 `innerHTML` 接真实内容，应把已选视觉方向映射为现有 `h(...)`：Header/ProjectPicker、SectionNav、SearchToolbar、RecordList/Table、RecordDetail、SourceReferences、JobDetail/CandidateComparison。真实用户文本仍由 React 文本节点处理；字符串不能拼成 HTML。状态由现有数据请求、已核对的 ID 与错误码驱动，沿用现有同源管理路由、locale 和权限边界。

当前 Host 仍从模块表 `require('react')` 取得 React，不能因借鉴 shadcn/Ant/Radix 就导入宿主未提供的包。整理、批量写入等新增接口在设计获准和独立验证前不得假接旧操作。
