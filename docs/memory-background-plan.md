# 05本地记忆：统一机制与自动运行设计说明

编号 **MEM-BG-1**，修订3，2026-11-08。本文集中记录此前讨论的分层、压缩、自动维护、纠正、引用及保留规则，作为05后续机制设计入口；用户体验沿用[MEM-EXP-1](memory-experience-contract.md)。新增机制是**设计目标，未实现**，已有v0.3.0底座保持原证据身份；本轮不改代码、安装profile或既有封存物料。本文不是项目完工的机制验收报告，不新增管理分区、批次选择、候选审批或发布操作。

05最缺的是“原依据→经验→后台核对整理→可靠召回→纠正反馈”的闭环，而不是更多记忆层级。

## 记忆层级与数据角色（BG-H01..H06）

**05按信息粒度使用两级长期记忆：具体经验→项目摘要abstract。** 原始依据、本次上下文、冷热存储和年度工作记录分别有自己的作用，不混算成更多压缩级数。

| ID | 角色 | 内容与作用 |
|---|---|---|
| BG-H01 一级：具体经验 | 可复用的约束、偏好、方法、纠正与带条件结论 | 保存经验正文、原始支持关系、来源版本及项目/仓库/工作树/构建适用条件；具体问题优先检索此层 |
| BG-H02 二级：项目abstract | 项目说明、主题概览和经验索引 | 短摘要帮助发现相关项目和主题；命中后按许可查具体经验，不把整个项目记忆注入模型 |
| BG-H03 原始依据 | 支持经验的获准对话摘录、事实来源及版本 | 独立于两级记忆，供回看和纠错；只保留必要材料，不复制全量历史。原文不可得时如实标明，摘要不能逆向还原丢失依据 |
| BG-H04 本次入模上下文 | 当前问题选中的索引、经验和必要依据 | 是一次请求的有界投影，不是另一级持久记忆；按问题、权限、版本和上下文预算选择，不整库加载 |
| BG-H05 热/冷存储 | 明细与索引的存放方式 | 热/冷是存储维度，不是第三级记忆；active的冷明细仍可按需召回，用户主动归档的内容不自动召回 |
| BG-H06 年度工作记录 | 项目、需求、问题探索及本人贡献/成果的独立材料 | 是与经验并行的用途，不是更高一级；保留来源及证明状态，不混入普通经验自动召回、归并或跨项目共享 |

主题归组和派生视图是一级经验的阅读/检索表示，不额外引入必须经过的第三级。项目可显式登记多个仓库，具体经验仍各自检查scope与版本；未知项目/范围先暂停相关记忆，不猜为全局。项目初始登记/启用与已有许可规则沿用既定决定，不增加日常维护步骤。

这里的“两级”是05自己的设计。此前对照的Claude Code公开记忆文件为索引与主题明细；计入会话来源可用三级解释。Anthropic通用dreaming研究图还区分原始记录、记忆笔记、Wiki等组织表示、本次注入上下文四个角色，**不能据此声称原生AutoDream固定有三级或四级**。只借鉴后台回看、纠错、重组与按需读取，不为对齐层数添加新产品。

## 提炼、压缩与后台巩固（BG-C01..C04）

基本链路：**获准来源→一级经验→二级项目摘要→按当前问题选择经验/依据→本次上下文**。压缩会舍去表达细节，来源与适用条件必须单独保留，不能把更短误当更正确。

| ID | 动作 | 必须保留/避免的行为 |
|---|---|---|
| BG-C01 首次提炼 | 当前获准开发对话提炼为具体经验 | 保留结论、版本、适用条件和来源；过滤重复叙述与瞬时操作流水；成功与失败经验都可记录，不规定只记失败 |
| BG-C02 二次压缩 | 有效经验归组、去重并形成项目abstract | 完全相同内容可归并展示，语义相近只形成有支持关系的未核验派生表示；矛盾或不同版本分别保留，不能强行合成一个规则 |
| BG-C03 后台巩固 | 增量积累、纠正或过时风险触发回看、比较、修正及导航更新 | 不每次写入都调模型；从有效原经验与可读证据重建，避免无限对“摘要的摘要”继续压缩；不覆盖原证据，不自动永久删除原经验，不将模型猜测升格为事实 |
| BG-C04 冷档后再整理 | 低频明细移入非C盘后，维护更短的摘要/索引并按需读取 | 语义整理与文件存储压缩不同；明细及证明仍独立保留，不能因冷档丢失来源。再次整理仍使用有效原经验/依据，不新增压缩层级 |

现有v0.3.0已实现一级经验提炼底座和二级的**抽取式**abstract：最多60条有效经验，每条截取至多240字符；这不是已经完成语义理解/巩固。上表的语义归组、自动反思、冷档再整理及下面的新体验仍须实现和验证。

## 自动共享、保留与删除（BG-P01..P03）

- **BG-P01 摘要发现与按需明细：**同一批准本地profile内展示可见项目abstract，供Agent判断相关性、选择索引；选中后只按既有共享许可检索相关明细，保留原项目、版本和构建条件，不复制成目标项目的新事实。“对外显露”指获准Agent/项目可发现，不是公网同步。已建立索引自动跟随来源最新有效内容，无需每次刷新重新确认。**相关性选择不产生读取权限**；当前v0.3.0的grant/revoke/refresh是用户动作，未来自动相关性索引须在既有许可内适配，不能让模型越权或凭空扩大共享范围，也不增设日常人工审批任务。
- **BG-P02 冷档与项目生命周期：**长期未有效调用的明细自动进入非C盘冷档；沿用原TODO的可改默认90天，后台扫描/压缩不更新有效使用时间。索引保持小，先摘要发现再按需读明细。项目注销/删除不连带忘记已保存经验，保留历史来源与适用性；源码或环境不可再核对时标历史/适用性未知，不能冒充当前事实，也不自动新增共享许可。
- **BG-P03 明确删除：**删除记忆即清除；想可恢复时用独立归档。明确删除须让相关正文、摘要、索引、派生表示、证据摘录、冷档和受控缓存不可继续恢复或引用，在途晚到结果也不能复活。清理故障期间先保持不可读，再后台重试；旧备份恢复仍服从现行删除权威。项目删除保留、低频转冷、用户归档和明确删除是不同操作。保留历史可追溯性不能绕过删除、授权或来源失效。

## 用户可见体验与年度记录（BG-U01..U04）

- **BG-U01 只看内容即可：**Harness内记忆中心默认展示短标题、摘要、项目、更新时间，选中后在侧边看正文、来源及适用条件；经验/年度独立。处理任务、共享和高级控制为可选次级入口，不成为使用前提。日常提炼、保存、巩固、索引、转冷及纠正由系统处理，无选批次、候选审核、发布或新建会话恢复步骤。
- **BG-U02 对话保持简洁：**过程只更新一个小bar，例如“正在记忆/正在整理/已更正/暂缓”；不把入库结果、记忆正文、候选差异或反思日志大段写入聊天。不能仅用CSS隐藏实际聊天消息来实现静默；后台详细记录留本地，点开时再看。
- **BG-U03 结论角标与短归因：**参考记忆形成的结论、接口判断或建议旁添加可点击角标，绑定结论ID→记忆ID/实际采用版本。回复末尾明确映射哪些结论参考了什么记忆，**整段≤100个可见Unicode码点**，包括标签、编号、标题与标点；正文不展开记忆原文。仅检索命中、已入模但未声明采用不标成影响，不承诺观测隐藏模型思维。超长时合并结论编号/缩短名称；仍超长则缩减本轮实际采用范围并重新生成，不能截掉映射或只删角标保留原结论。展示前须完成引用有效性及格式校验。示例：`记忆影响：①参考记1“内核构建约束”；②参考记2“跨仓测试记录”。`
- **BG-U04 年度材料：**开发过程中自动形成项目/需求/问题探索的粗粒度工作草稿，保留事实来源、个人贡献与成果、证明文档引用及待补证标记。必要时在对话中用一句短提醒请附证明，不变成日常记忆审核任务。最终报告由用户审定后本地导出Markdown/JSON，属于既定报告交付流程。《年终总结维度.md》未提供，维度映射保持待参考，不能猜测考核或评分标准；不阻塞先记事实。

自然语言纠正遵循下文“先止错、后反思”：明确纠正及时替换后续可用版本，并同步让旧摘要、共享/派生贡献及本次投影失效；旧回答不篡改，角标可显示“已更正”，旧依据只有仍保留且获准时才可查看，已清除则显示不可用。根因区分过时、理解偏差、项目/版本错配、证据不足和未知；假设单独标明，不凭一次纠正推广全局规则。反思仅留后台，不自动修改全局skill。

## 只增加一个后台worker

**正常聊天→自动记录有价值的经验→变化合并入队→空闲时核对/整理→自动更新导航→下一答按需引用。**

纠正与删除走即时失效通道，不等worker。普通巩固仅处理一个具体scope的增量与必要邻近经验，项目级导航在各scope分别核权后聚合。项目已经启用记忆且有有效授权时自动执行；用户不用启动任务、挑条目、审核或重建会话。

默认调度按下节的“待处理条件＋空闲窗口＋发送前复核”运行。优先级为纠正/删除、疑似过时且实际采用过的经验、新经验归组；不声称使用频率能证明记忆正确。归档和过时检查均按条件判断，不能仅因“很久”就判错。

### 自动触发与空闲调度（BG-S01..S05，拟实现）

插件由**Harness宿主端**执行监听、计时、入队和Provider调用，不依赖聊天中的“继续”、Agent主动调用工具或记忆面板保持打开。只有条件满足才发模型请求，定时检查本身不调用模型，不向聊天伪造用户指令。

| ID | 规则 | 拟定默认及边界 |
|---|---|---|
| BG-S01 记录变化并唤醒 | 经验新增/纠正/来源失效时更新本地dirty标记；变化事件、前台任务结束及低频定时器唤醒同一调度器 | 事件先登记、不直接发模型；去重合并相同变更。计时器只查dirty/队列/Host状态，不扫描整库；没有新变化不调用模型 |
| BG-S02 判断是否到期 | 普通变化累计达到阈值，或最早待处理变化达到等待上限，才进入可调度状态 | **10条变化或等待1小时**；这是新语义巩固的默认值，不能误改现有抽取式abstract的24小时配置。明确纠正/冲突优先入队；删除与停用旧值立即本地执行，反思仍等空闲 |
| BG-S03 判断是否可运行 | 已启用项目、许可/来源有效、预算可用，且Host可确认所有会话及子任务无前台模型生成、工具执行或排队请求，持续一个静默窗口 | **连续30秒**；切后台、鼠标不动或没有新消息不能单独算空闲。Host状态未知/断档则延后，不猜测；真正dispatch前重新核当前状态及授权、预算，并通过可信适配仲裁前台优先，不能只检查一次后异步发出 |
| BG-S04 小批次并让路 | 一个worker一次处理少量经验，每批结束重新检查条件；用户新消息、前台任务入队时立刻停止派发后续批次 | **最多5条、后台并发1**，仍受已有输入/输出与预算上限约束。前台不等待整理结束；已发出的请求尽力取消，取消不证明服务端停止或费用撤销。未确认完成则按unknown处理，不自动ack/重发；结果返回也须复核来源版本/授权/代次，不能恢复旧值 |
| BG-S05 生命周期与恢复 | dirty标记、最早变更时间和任务状态持久保存在本地，宿主停用时移除监听/计时器并停止新派发 | Harness宿主服务运行且插件加载时才工作；仅关闭面板不停止，关闭窗口是否停止取决于宿主服务是否仍运行。服务退出/电脑休眠时不执行；首版不新增系统常驻服务。恢复时重置30秒窗口、重核Host状态与当前许可，未发送的任务重新核源后排队；不能复用旧lease，发送中断按unknown对账，不自动重跑，也不追赶休眠期间每次错过的定时点 |

执行顺序：**变化落本地→到期检查→可信Host静默窗口→原子派发准入→有界后台Provider请求→校验/切换本地有效表示→小bar更新**。持续忙碌或预算不足就保留待处理状态，普通聊天和现有有效经验检索继续，不强插整理、不要求用户清队列。一次小bar即可表达“正在整理/已整理/整理暂缓”，详细任务记录只供可选查看。

已有底座见`plugin/index.mjs`的`scheduler.start()`与抽取式摘要维护计时器、`plugin/scheduler.mjs`的`setInterval`及并发控制。**它们不等于已经具备全Host空闲信号或语义巩固。** 前台状态聚合与dispatch优先权仲裁是待核验的本地适配合同，不虚构Host方法；若不能接入，不发此类后台模型请求，保持该增量未交付。后台批次授权仍按下文独立manifest/可信签发执行，计时器自身不产生权限。

### 自动采用不等于自动认定正确

- 本地校验来源权限、实际版本、正文/摘要长度、引用完整性及输出结构；版本变化的晚到结果直接丢弃。结构通过不能证明语义正确，模型自评分也不能作为证据。
- 完全相同的原文可自动归并展示；语义相近只生成带原始支持关系的“模型归纳、未核验”派生表示，不删除不同版本或矛盾原经验。支持不清的新增断言不进入可用派生表示，保留原经验继续检索。
- 新索引/派生版本先在本地暂存，再核当前来源和删除权威后切换；失败保持原先仍有效的表示，已失效旧版不能回退复活。长期不把“摘要的摘要”当唯一依据：重新整理从有效原经验及获准证据读取。
- 摘要用于发现和导航；凡采用派生表示形成具体结论，必须能回到有效原经验/获准证据及适用条件；无法建立支持关系时只作导航，不采用新增断言。引用存在仍不证明语义支持已核实，不能把未核验内容变成事实。分组/推断可以保留，但须明确条件和未核验状态。

### 纠正先止错，反思后完成

能从当前引用与用户明确纠正定位时，立即停止旧版后续使用；新值来源是本次用户消息，不冒称独立验证。含否定、引用他人观点或范围不明时，不自动覆盖猜测出的事实；先暂缓可定位的争议内容，普通聊天继续。确实影响当前结论而无法判断时，最多作必要的事实澄清，不要求管理记忆。

后台比较可取得的原来源与纠正消息；没有材料就记录“原因未知”。可得到带条件的预防规则，例如“引用构建约束前核对目标内核”，仍作为经验，不自动修改全局skill。反思失败不阻塞纠正，不能因迟到整理重新引入旧值。

## 实施接缝和失败出口

优先复用本地SQLite、受控Provider、调度器与删除权威，不增加新服务、向量库或完整Wiki。`provider.mjs`当前仅3个用途、`jobs.mjs`仅当前片段/用户摘要，`host-grants.mjs`绑定消息receipt；**不能把旧消息receipt当未来后台授权**。后台需要独立的有界批次manifest（scope、源ID/版本、输入摘要、purpose、route、授权代次）及可信Host签发/重核；沿用已启用项目策略与批准Provider，不由模型自行授权。无可用接缝则保持此能力未交付，不伪造API或追加人工批次审批来凑闭环。

新增最小证据存储须服从相同scope、来源撤销、删除账本和本地容量限制；明确删除要清正文及派生副本，不能在历史版本、冷档或摘录里复活。已有记忆没有原片段时只作memory-only归组，不推断其根因。年度工作记录继续独立，保留贡献、成果及证明来源，不进入普通经验归并；最终报告审定沿用原要求。

网络仍仅走现行批准的Harness Provider；本地保存索引、摘录和反思，不新增遥测、同步或托管存储。共享只读既有许可，不因自动整理扩大范围。队列在结果未知时不自动ack、不盲重发；受影响后台任务暂停，普通聊天继续，不要求用户核对队列或放行。仅有可信对账证据后才恢复；没有证据可持续保持暂停，小bar显示一次简短状态。

`session-hooks.mjs`目前通过记忆来源消息追加召回，`final-projection.mjs`会阻断过时投影。新体验不能仅用CSS隐藏长消息：真实Host必须证明能重建本次插件贡献、清除自己的失效历史正文且不改用户消息，再继续普通聊天；这个接缝仍是交付门禁，不能以“停用新增召回”假装旧正文已消失。
