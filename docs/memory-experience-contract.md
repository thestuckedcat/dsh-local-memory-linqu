# 05记忆体验：看得见，自动管，少打扰

编号 **MEM-EXP-1**，2026-11-08。依据用户最新四点要求收束，作为05现行产品体验合同；本轮交付设计与合成演示，**尚未修改运行插件**。旧v0.3.0实现、测试和安装保持原证据范围。

## 用户实际使用

你正常与Agent讨论开发问题，记忆在后台自动形成、整理和更新。想看时打开Harness里的“记忆中心”，直接看到“记住了什么”；不需要挑选批次、审核候选、发布记忆或处理队列。发现不对，在对话里直接纠正即可。

| ID | 用户能看到的行为 | 默认规则 |
|---|---|---|
| EXP-01 | 记忆中心直接列出短标题、摘要、所属项目和更新时间；点开看来源与适用条件 | 以内容阅读为主，保留经验与年度工作两个分区；处理任务、共享和高级控制收进次级入口，不要求使用 |
| EXP-02 | 不做日常记忆维护 | 项目已启用及授权范围内，自动提炼、保存、整理、更新、维护索引；自然语言纠正也自动处理。可选查看、停用、归档、明确删除仍保留，不成为前置步骤 |
| EXP-03 | 对话旁仅一个小bar，如“正在记忆…”“记忆已更新”“记忆暂缓” | 不往消息区插入长篇入库结果、摘要、记忆列表、候选差异或反思日志；普通后台失败不让用户管理队列 |
| EXP-04 | 受记忆影响的结论或接口建议后加角标，点击定位对应记忆 | 回复最后追加一段精简映射，**整段不超过100个可见字符**，说明哪些结论参考了哪些记忆；未采用记忆时不加 |
| EXP-05 | 直接说“这里已经改了”“上次理解错了”，系统及时更新 | 先停止采用被纠正的旧版本，再保存有来源的新事实并后台反思；聊天仅用“记忆已更正”等短状态，不展示长反思 |

## 一次回答的样子

> ① 按目标内核版本准备构建环境。〔记1〕  
> ② 测试结果同时记录驱动和用户态组件版本。〔记2〕  
> 记忆影响：①参考记1“内核构建约束”；②参考记2“跨仓测试记录”。

角标是可点击的记忆引用；短名只是显示标签，实际绑定记忆ID、版本及结论ID。点击在记忆中心看来源，不把正文展开进聊天。

“影响”具体指Agent在本次回答中**声明采用、且引用校验有效的依据**，不是对模型内部思维的因果测量。仅检索命中、提供给模型但未引用的记录不能冒称影响了结论。模型提炼不等于已经核实。

计数包括“记忆影响”、编号、标点及短名，按Unicode码点计数，角标展示在结论旁。优先合并相同来源的结论编号、用短标题；无法在100字内完整表达时，缩减本轮实际采用的记忆并重新生成，不能截掉映射、漏报来源或悄悄隐藏超限部分。全文与引用校验完成再显示最终回复，不能先把未核对的归因当成事实展示。

## 纠正后系统做什么

1. 从当前对话和引用定位被纠正的记忆、项目、适用版本；确定的旧记录立即退出后续召回，同步使其旧摘要、共享引用和派生视图失效。
2. 把用户的纠正连同当前消息来源保存，标注“用户纠正”，不冒称外部证据已验证。不扩大到别的项目或版本；确实无法判断纠正对象/范围时才作一句必要澄清，已识别的争议内容先暂停采用。
3. 后台回看获准原来源的实际版本，与纠正消息比较，再检查原因：信息过时、理解偏差、项目/版本错配、证据不足或原因不明。无法取得来源时根因保持未知或假设。可证实的原因与模型假设分开；不把猜测写成根因，不把一次纠正扩写成普遍规律。修正规则须有适用条件，不自动提升权限或改动全局skill。
4. 更新索引后继续正常使用，用户无需审批发布或新建会话。再次回答须使用有效版本，并保留纠正来源；旧回答的角标可以显示“已更正”，不篡改历史回答。

这里借鉴既有[整理设计](memory-consolidation-design.md)所列AutoDream/记忆巩固思路中的“后台回看→比较证据→修正→整理”，**只借鉴机制**。不接入第三方托管记忆，不声称已经复刻Claude Code内部实现；本轮没有新增源码复用或外部服务。

## 保留的边界

自动处理仅作用于已有授权、范围和预算内的内容；共享许可仍由有效授权决定，Agent不能自行扩权。模型只走已批准的Harness Provider，存储、索引、管理和反思记录留本地；不新增遥测、托管记忆、同步或其他模型接收方。

普通自动整理保留可追溯的原始证据，不自动执行用户语义的永久清除。明确删除仍须清除相应正文及派生副本，不能被摘要/归档恢复。项目删除与记忆删除不同；冷档、跨项目与年度记录仍遵循既有边界。年度自动草稿继续独立保存，最终年终报告由用户审定，不等于要求用户管理日常经验记忆。

源内容可以作为受控上下文发给批准Provider，但不作为大段聊天消息呈现。不能靠CSS隐藏聊天正文来假装实现了静默记忆。

Host适配必须证明可重建本次插件贡献、移除失效记忆及自己的旧工具正文，且不改动用户消息；若做不到，暂停受影响的记忆贡献，普通聊天仍继续，不能要求用户换会话。此接缝、角标渲染和发送前/展示前校验均是**待实现、待真实Host验证**的要求，不冒称现有Host已经支持。无法排除旧贡献继续入模时，必须先解决宿主适配，不能将该路径标为本体验已交付。

## 局部实施待办与验收

下列是对现行TODO的体验增量，未执行。先实现最小“自动记住→查看→引用→纠正”旅程，再接自动整理/冷档；不让用户先做手动整理来获得主体验。

- **EXP-T1 直观阅读**：默认列表就能知道记住什么，来源可点，经验/年度不混杂；无需打开处理任务才能看内容。
- **EXP-T2 静默自动化**：自动记录和维护，无批次选择/候选审批/发布/新聊天步骤；所有后台过程只更新小bar，常见失败自动降级或恢复。结构、来源或支持关系校验失败的候选不保存、不采用，只暂停受影响的更新/贡献，普通聊天继续。未知结果不盲目重发，必要授权/事实澄清仍如实给出最小提示。
- **EXP-T3 可核对引用**：结论ID→记忆ID/版本的结构化映射；只接受本次有效且获准的引用；仅命中未采用不显示；结尾映射总长≤100字。角标/结尾归因格式不合法时重新生成，不能给无效引用补“已核实”。
- **EXP-T4 及时纠正**：自然语言纠正后，下一答不再采用旧版本；派生/共享均失效；反思区分事实与假设；跨项目误改负例不通过。
- **EXP-T5 自动维护**：将既有整理设计的授权、迁移、预算、unknown、删除约束适配到自动队列；移除旧手动发布旅程，不照旧计划直接开工。
- **EXP-T6 真实集成**：隔离Host证明小bar/角标接缝、失效上下文清理和普通聊天连续性；之后再按已有授权安装与合成Provider测试，未验证前不称产品完成。

以上可局部新增/微调，稳定ID保持不变。旧整理R2/55步计划与A/B面板只作为历史技术参考；其中手工批次、显式发布、长篇候选管理及“失效后新聊天”默认路径已被本合同取代。其旧评审不覆盖这次自动化与引用新行为。
