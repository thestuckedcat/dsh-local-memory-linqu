# 可指导编码的软件设计合同

版本1.0，2026-11-06。适用于七份`<能力>/docs/software-design.md`，05本轮使用统一`TODO.md`承接已完成实现和新增产品要求。章节可按复杂度合并，不以字数或固定标题代替内容完整性。

## 必需内容及退出条件

| 最终功能形态 | 用户入口、载体skill/plugin/MCP/profile、首版能力、后置项、主要正常/失败旅程、和其他模块的关系 |
| 架构与代码布局 | 进程/信任边界图或时序、具体文件/模块职责、启动/卸载/资源所有权、哪些复用/薄适配/自实现 |
| 数据与持久化 | 字段、ID、版本、索引/路径、来源/适用条件、凭据引用、事务与迁移、保留/归档/删除及崩溃恢复 |
| 接口 | 每个必需工具/RPC/CLI参数和返回结构、错误码、权限/期望版本、分页/容量、重复请求、取消和超时语义 |
| Host与依赖适配 | 已核API/位置/摘要与本地定义接口分开；服务不存在时的确定禁用/替代路径；固定依赖/许可与离线准备门禁 |
| 状态与并发 | 状态集合和允许转换、单writer/锁/序列、幂等键、资源lease、重入、版本变化、unknown如何恢复 |

| 实施任务 | 有依赖顺序的增量、具体增改文件/接口、最小失败用例、验证命令及预期、外部条件与临时fixture |

| 局部修改 | 稳定需求/接口/验收ID、影响映射、版本/迁移规则和局部新增/微调示例 |

## 接口精度

以下是精度示例，不强制所有模块使用相同内部字段名：

```ts
type OperationRequest = {
  schemaVersion: 1;
  operationId: string;
  scopeRef: string;
  expectedRevision: number;
  input: FeatureSpecificInput;
};
type OperationResult = {
  operationId: string;
  state: 'completed' | 'partial' | 'outcome_unknown' | 'refused';
  currentRevision: number;
  evidenceRefs: string[];
  errorCode?: string;
};
```

设计必须将FeatureSpecificInput具体化；不能把示例留成核心功能的空白参数。人可读说明与类型/schema一起定义约束和副作用。

跨能力事实事件沿用[共同合同](development-contract.md)的v1 snake_case字段：schema_version/event_id/kind/source_capability/scope_ref/session_ref?/operation_id/generation/affected_refs/outcome/before_snapshot?/after_snapshot?/occurred_at。新增kind或语义变更要单独版本化，不能冒称现有05消费者已支持。项目登记删除、会话移除、源码工作区恢复、永久删除记忆是不同事实。

## 不确定性处理

- **可配置参数**给schema、可配置设计默认值和验证规则，不要求用户提供每个具体数值。
- **本机未核API**不能命名成确定存在的方法；定义本地适配接口、实现分支、能力探测和拒绝行为，注明实际Host绑定证据。
- **核心功能不可实现**必须明确阻塞或产品级替代，不能用隐藏/归档冒称永久删除，用独立浏览器冒称原内置页。
- **依赖准备**没有确切许可/固定字节时不启用候选；提供无需该候选的确定首版实现或将该功能明确为运行门禁。
- **运行输入缺失**如站点、服务器、符号路径、编译配置不阻止定义完整接口；实施/真实验收时按明确参数提供，不猜测目标。

## 可编码性审查

评审者应能从文档回答：先写哪些文件、每个模块收到什么/返回什么、状态保存在哪里、失败后做什么、何时有权读写/发送、如何验证、局部修改影响谁。无法回答的核心问题必须补设计，不能仅列“待开发时确认”。

设计验收不认证运行成功。实施时锁定最终依赖/构件、重新核宿主、真实测试与独立审查仍按各模块门禁执行。
