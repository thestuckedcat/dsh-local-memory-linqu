# 插件完成后的 Harness 安装与 API 测试计划

更新：2026-11-04。当前为后续执行计划，**尚未安装或调用API**。用户已授权：插件完成后可使用、直接打开DeepSeek Harness安装，并用已注册API测试。同范围操作无需再次确认；本授权不改变“本轮先完成目录、形态和独立开发计划”的范围。

实施顺序：[05→07→08→06→03→04→02→01](execution-order.md)。各模块先独立交付，08第三阶段先交付框架与05/07接入，之后逐项验组合。仅skill或本地CLI不伪装成可安装plugin；02的本地MCP通过宿主支持的配置入口注册，另验stdio和真实可信目标。

## 安装前的可审查结果

1. **固定构件。** 在对应模块目录记录源码commit、包/所有运行依赖摘要、许可物料、运行时、所需服务与导出、允许的网络目的。启动不执行安装/下载脚本；不使用latest。调查版本不等于准入版本。
2. **真实宿主核对。** 只读检查安装包版本、运行实例及目标profile。当前已知安装基线为0.2.1-rc.5，另有0.2.2-alpha.2源码；安装时必须重新核对。版本/服务不兼容则拒绝安装并记录阻断原因，不自行升级或套用另一份源码的兼容结论。
3. **独立行为与出口验证。** 按模块PLAN执行真实存储/协议与contract用例、隔离宿主测试、故障恢复、卸载清理。负向出口测试覆盖实际加载代码、子进程与浏览器资源/重定向；只能访问明确登记的模型API或当前可信目标。测试应主动制造未知endpoint、遥测、更新/下载尝试并确认拒绝，不能只用grep无fetch或一次无连接作证明。
4. **独立评审。** 设计/实现者与审查者不同。审查最终字节、复用依赖闭包、秘密路径及测试证据；阻断问题修复并复核后，才将对应模块标为可安装。不存在Git基线时使用文件清单和SHA256，不虚构提交。

## 安装和激活

- 从宿主支持的plugin manager安装本地已审目录或固定制品，保存精确bundle/plugin标识、版本与开关结果。允许按任务需要直接打开DeepSeek Harness。正式profile由宿主管理器修改，不手工重写C:/Users/admin/.dsh下的包或patch文件。
- 安装前通过宿主支持的方式记录非秘密配置和当前启用清单，明确该模块的禁用/移除恢复步骤。不导出credentials或完整会话备份，不因安装而扫描全部历史。
- 分别确认保存、加载、激活和功能状态；failed、overridden、restart-required等如实保留。更新模块需要的重启按宿主机制执行，不能把保存成功当成已生效。
- 首次只启用当前模块及必要依赖，08只装已审选择项。不安装默认全家桶，不启用通知/同步/市场拉取/公网中转。未知构建脚本先停止该制品安装并审查，已有授权不等于批准任意依赖脚本。

## 已注册 Provider 的真实测试

- 模型路由从Harness现有已注册Provider取得，使用宿主Provider/credentials接口，不输出、复制或转存API key，不扫描其他环境变量或CLI密钥。新建专用合成会话；不采集用户原会话。
- 优先用隔离测试profile和宿主支持的Provider引用；若无法跨profile引用，保留凭据在原宿主，在已授权安装目标中使用专用合成会话测试。不得为隔离而复制明文密钥。
- 每次测试固定Provider、model、目的、scope和request ID。单模块首轮最多3次模型请求，每次输入上限8000字符、输出上限2048 tokens；能本地验证的操作不调模型。超时/断线不自动重试、不切其他Provider，计费/结果未知标outcome_unknown。若模型接口无法施加输出上限，先改适配器。
- 05最低真实旅程：合成来源提炼→本地持久化→新合成会话同scope召回→异scope不召回→更正/删除后不召回。再做断模型下本地检索、重启、在途删除及旧正文备份恢复测试；注入已知假秘密验证过滤。模型内容质量与生命周期正确性分别记录，不能用单次漂亮回答代替验收。
- 07验实际组装上下文与UI读数的一致性；08验已选05/07装配与卸载。其他模块按自己的PLAN测试。对03的删除/回退只操作明确的合成会话/文件；02只连用户指定可信目标；01只在提供相应目标/凭据引用后验证认证，不猜测真实账号或服务器。

## 证据与恢复

在模块evidence目录保留时间、构件摘要、实际宿主/profile非秘密标识、精确操作、通过/失败/skip/unknown、网络测试范围及限制。输出脱敏；不记录真实密码、cookie、token或请求Authorization。既有模型调用无法撤回，删除本地记忆不宣称删除Provider已收到的数据。

激活或旅程失败时先禁用/移除本次组件，按宿主支持的机制恢复之前选择并复验；回执前崩溃或部分成功保留partial/outcome_unknown。恢复不删除用户原会话。只有对应能力与证据完整时才更新capabilities.json；通过独立测试、可安装、已安装、真实功能通过是不同状态。

自动升级Harness、注册新模型服务、导入真实历史、连接未指定服务器、发送外部通知或发布包均未包含在本授权中。需要新增条件时说明具体缺口；已经授权的本地安装和注册Provider测试不重复询问。
